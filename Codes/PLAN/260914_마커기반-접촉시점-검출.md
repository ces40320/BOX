## 3. 정책 (2026-09-16 확정)

| 우선 | 내용 |
|------|------|
| 1 | 완벽 검출보다 **분석 가능한 표** — 세그먼트 공란을 조용히 NA로 두지 말 것 |
| 2 | 살릴 수 있는 조건은 적응 임계·배정으로 **칸을 채움** (과한 휴리스틱 남발은 지양) |
| 3 | 죽은 트랙·불가 조건은 CRITICAL로 명시하고, **그 셀은 통계에서 제외 또는 별도 민감도** |
| 4 | “전역 매칭으로 완벽 재설계”는 **필수가 아님** — 공란만 줄이면 됨 |

### 3.1 공란이 남을 때 쓸 수 있는 통계 (추천)

이미 LMM을 쓰고 있으므로, **불완전 균형(unbalanced)** 은 모델이 감당 가능하다. 다만 **셀 공란 vs 조건 통째 결측**을 구분한다.

1. **Available-case / unbalanced LMM (1순위, 현재와 친화적)**  
   - 관측된 (sub × cond × section × app) 행만 넣음.  
   - 리포트에 **셀별 n**, 결측 패턴 표 필수.  
   - `statsmodels` MixedLM / 현재 `stats_lmm.py` 흐름과 맞음.

2. **Complete-case는 “조건 단위”로**  
   - 마커가 죽은 조건(예: SUB4 10kg_10bpm)만 마커-app 행에서 제외.  
   - RiCTO·MeasuredEHF 행은 유지 가능 → app 비교 시 **표에 n을 병기**.

3. **패턴 기술 + 민감도**  
   - 결측이 MAR에 가깝지 않을 수 있음(궤적 품질·템포).  
   - 주분석 = available-case LMM, 보조 = “마커 완전 세그먼트만” 재추정해 계수가 뒤집히는지 확인.

4. **다중대체(Multiple Imputation) — 선택**  
   - 시점 오차·RMSE 같은 연속 결과에 한해, 보조 분석용.  
   - 본문 주력으로 쓰기엔 가정 설명이 무거움 → supplementary 후보.

5. **비권장**  
   - 공란을 GT/이웃 cycle로 **조용히 채운 뒤 표본처럼 쓰기** (방법 비교 오염).  
   - 공란을 0 오차로 코딩.

**실무 제안:** 마커 app은 (a) 칸 채우기 최선을 다하고, (b) 남은 공란은 LMM available-case + n 표, (c) 죽은 조건은 마커 행만 드롭. RiCTO 주분석은 공란 이슈와 분리.

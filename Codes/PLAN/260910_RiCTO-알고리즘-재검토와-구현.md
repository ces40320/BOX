## 1. 배경·목표 (공유 언어)

- **목표**: 손 로드셀(**MeasuredEHF**)이 없을 때도 상자 들어올리기 중 **손 외력(EHF)**과 접촉 창을 추정한다.
- **HeavyHand**: 박스 질량을 손에 상시 얹은 단순 추정 → grip–deposit 전이가 계단처럼 보여 pelvis residual·L5/S1이 과대추정되기 쉬움.
- **preRiCTO / postRiCTO**: residual 시계열로 전이 파라미터 `(t1,d1,t2,d2)`를 찾고, BK 손 운동학으로 추정한 힘에  
  - pre: 사각 가중(rect)  
  - post: 스무스 가중(smoothstep)  
  을 곱해 ExtLoad에 넣는다. (구칭 **RMO** → 학회 투고 시 **RiCTO**로 개명, 근간은 동일해야 함.)

**Sensorless 원칙**: pre/post ExtLoad 생성 경로에 MeasuredEHF 손 힘·토크·COP가 **들어가면 안 됨**. MeasuredEHF는 **검증(GT)** 전용.  
**GRF**: force plate 측정값은 **유지** (손 센서만 제거). GRF까지 없는 트랙은 Strategy C 장기 옵션.

## 2. 처리·정리한 내용

### 2.1 개념 정리 (구현 전 논쟁)

| 논점 | 정리 |
|------|------|
| pre는 HeavyHand 이후? | HeavyHand(또는 동등 질량 얹은) MOT·잔차/ID를 입력으로 쓰는 흐름이 맞음. |
| SO `residual_pelvis_ty` vs 힘 임계 | 최적화 타깃은 **잔차(또는 ID pelvis_ty)**. MeasuredEHF 5 N은 **비교용 GT**이지 센서리스 경로의 이벤트 소스가 아님. |
| pre도 `(t1…d2)` 최적화? | 시점·폭은 잔차 피팅으로 잡고, pre는 같은 구간을 rect로, post는 smooth로 적용. “pre만 따로 다른 시각”이 아님. |
| pre/post를 **동일 시점**으로만 자르면 pre가 무색? | 정량 비교는 GT(5 N) 창으로 맞추는 쪽이 타당. 마커 독립 비교는 보조·한계 논증 ([260914…](./260914_마커기반-접촉시점-검출.md)). |
| 레거시 estimated_original 이벤트 | 과거 MOT 샘플로 force threshold vs residual 근거를 대조 확인. |

### 2.2 레거시 비교 문서

- `get_optimized_solution_and_EHF.py`(학회 RMO) vs `ricto_core.py`(후배 수정) 절차 비교 md 작성 → `Codes/COMPARE_…md`.
- 사용자 밑줄 = “이렇게 바꾼 게 합리적인가?” 의문 목록으로 사용.

### 2.3 비판적 결정 → 모듈 구현 (RICTO_PLAN)

| 항목 | 후배 `ricto_core` 문제 | 결정 |
|------|------------------------|------|
| MOT 템플릿 | MeasuredEHF 복사 후 vy만 교체 | **HeavyHand MOT** + 손 12컬럼을 운동학으로 재기입 |
| 힘 축 | vy만 | **fx,fy,fz 전부** `w·f_est` |
| torque | Measured 유지(누출) | **0 강제** |
| COP | Measured 유지 | **BK hand COM** |
| 좌우 | 확인 필요 | **force3=L, force4=R** |
| 축 부호 | 축별 −1 혼재 | **`f = −m_h(a−g)` 통일** — **결정 완료** (사용자 플롯 확인 중) |
| 가속도 | BK acc + despike | **pos 2차 미분**, despike OFF |
| baseline | median top-30% 등 | **`B = m_box·g`** |
| 잔차 | SO | **ID `pelvis_ty_force` 기본**, SO fallback |
| 솔버 | Nelder–Mead만 | 플러그인; 기본 **least_squares** |

구현 위치: `Codes/c_Run_Tools/optimization/` (`ricto_*.py`, `run_ricto.py`, `validate_ricto.py`).

### 2.4 검증·운영 결정

- 접촉 GT 임계: **5 N**으로 고정 (2 N 비교 후 5 N이 나음; 2 N 산출물은 삭제, 코드 스위치는 유지).
- 축 매핑(플롯): 피험자가 −z를 바라봄 → ML(x)·AP(z) 부호 규칙 반영; Measured=검정 점선, pre=빨강, post=파랑.
- `validate_ricto.py --all`, 실데이터 corr/RMSE/시점 오차.
- 부호 더미 테스트 PASS (`RICTO_PLAN` §9.1). 합성 CSV는 Analysis에 **쓰지 않음**.
